# 工作簿差异的有界数据管线

## 目标与边界

所有桌面工作簿比较使用同一条生产链路：Electron 启动一次性 Rust 进程，Rust 负责解析、规范化、对齐和比较，Electron 管理临时结果，Canvas 按视口读取并绘制。保留既有 strict/content 规则、行对齐、合并单元格语义和三种布局。

不通过放宽 XML、stdout、堆内存或超时上限解决容量问题。不引入常驻 Rust 服务、另一套比较算法或按文件大小切换的两套实现。

## 失败原因

100000 × 200 的有效 XLSX 含 2000 万非空单元格，单张 worksheet XML 解压后超过 1.2 GB。原实现先读完整 XML，再同时保存单元格、行文本及两个签名；密集差异又复制两侧值、公式及 JSON。前端虽然虚拟绘制，绘制前的数据模型仍展开整表单元格。

原 XML 条目上限只是在最早阶段暴露问题。单独流式解析也不足以避免后续全量 DTO 和前端模型耗尽内存。

## 数据职责

| 层 | 保存和处理的数据 |
| --- | --- |
| Rust ingest | ZIP 解压事件、当前行、规范化单元格；逐行写磁盘 store；同一扫描收集 worksheet 元数据 |
| Rust comparison | 轻量行索引、现有对齐规则、精确比较、变化列区间与统计；strict/content 共用规范化数据 |
| Artifact | 不可变规范化单元格、物理行索引、独立模式对齐索引及变化摘要；manifest 标识格式版本 |
| Electron | 受控临时目录、来源与结果的生命周期、只读窗口访问、有界缓存、独立线程直接扫描搜索 |
| Renderer | 行坐标和变化摘要、虚拟布局、可见/冻结/合并锚点/选中单元格窗口；不保留整表值和公式 |

共享字符串也必须流式写入可索引 store，并使用有界缓存。唯一 inline string 不进入全表 intern map。

哈希仅用于候选筛选；判定相等及匹配锚点时精确验证原始规范化内容。解析错误、截断及磁盘写入错误必须终止准备，不返回部分表格或假空表。

`.xlsb` 和 `.xls` 进入相同的规范化 store。XLSB 使用 calamine 公开单元格事件接口，观察实际值范围、写稀疏公式流，再逐行写值；不依据可能过大的 dimension 分配密集矩阵。XLS 先写公式流并释放公式 Range 副本，再取得值 Range，减少应用层同时驻留的复制。公式 scratch 在成功和错误路径均关闭删除。

格式读取库的能力仍需分别界定：XLS 的库内全书 Range 缓存与 XLSB 的全量共享字符串表尚无法通过公开接口关闭；不能将格式事件接口宣称为整个进程内存恒定。

## 窗口与全局状态

全局统计、minimap、差异筛选与导航依赖完整差异索引，不依赖已缓存窗口。区分最大物理行号、实际存储行数和对齐后的显示行数。

变化区域按现有八邻接规则连接。连续变化用列区间/矩形表达，带孔几何保持准确；独立区域数量巨大时使用全局紧凑索引，只为当前需要的区域生成摘要，不能让每个变化单元格或每个区域成为常驻 JS 对象。跨窗口合并按原始 anchor 额外读取。

窗口响应确认已读取的行列范围。未加载、真实空值、单元格不存在是不同状态。选择、公式栏、tooltip 和复制取得真实值；过期版本响应不得写入当前窗口。

64 × 16 的逻辑缓存桶只存储本次实际请求的显示行。连续行合并读取，稀疏差异行不会预读中间几十行。缓存同时计算字符串、行、区间及索引槽的开销，窗口与精确单元格共用 24 MiB 预算；精确读取另有 4 MiB 子预算。单个完整超长值是明确的不可拆分例外。读取最多四个并发，通知按帧合并；ready 等全部排队读取完成，并确认连续两帧状态稳定。

## 搜索与自动列宽

搜索保留 JavaScript RegExp 语义，包括 lookbehind、backreference 和跨单元格 tab 匹配。删除行搜索 base；替换对按原顺序搜索 base、mine，匹配锚点只搜索 mine。搜索值、公式及单元格分隔符，跳过内部 sheet/row 协议标记。专用搜索线程直接从私有结果目录读取规范化行和对齐索引，按显示顺序仅读取需要搜索的一侧；不经过主线程窗口、高亮对象或分页 IPC。文件读取使用有界预读，取消和释放等待线程实际退出。

自动列宽由全部选中列共享一次扫描，用原有 Canvas 字体测量规则计算；不能改成抽样。达到现有最大列宽后，该列后续值不可能改变结果，因此可停止读取这一列。完成宽度按不可变 provider、sheet 和字体/字体加载/缩放身份缓存，关闭时释放；菜单和表头操作共享取消所有权，手动调整列宽或新操作使旧结果失效。

主进程窗口和源行读取共享 16 MiB 预读缓存，按完整底层 Buffer 大小计费，邻接行合并文件读取；超大行仍流式跳过未选单元格。搜索和自动列宽是用户触发的完整扫描，不阻塞首屏准备。

## 生命周期

临时结果属于比较标签。切换布局和模式复用规范化 store；来源变更建立新结果，准备成功后替换旧结果，失败保留旧可用视图。

会话创建时保存不可变的来源路径与保留输入快照的映射，内部读取使用快照，显示使用来源路径。当前左右来源和版本是有序状态，不能用首次打开的左右路径覆盖新的结果。双文件换边通过原生操作整体交换来源 context 和已选版本；独立 Git/SVN 历史必须随对应文件移动，不能重新选择默认工作副本，也不能向另一侧仓库读取原侧版本。失败保留原有来源和结果。

相同来源的并发准备共享计算，由最新来源事务拥有提交权；只读请求加入准备时保留已有事务的提交检查。来源 context 与 artifact 在同一同步提交段切换，过期候选在旧结果释放前被拒绝。

取消先使版本失效，再停止请求和扫描，终止准备进程并等待实际退出/文件关闭，最后清理临时目录。异常退出的遗留目录应可回收。限制并发准备，缓存按字节预算淘汰。

返回当前已准备版本时，也取消正在准备的不同版本。旧结果清理失败不能删除已提交的新结果。复制、列宽计算的迟到响应确认比较、模式及用户修改版本后才更新界面。

## 验收

1. 使用经过地址、值、XML 和 ZIP CRC 校验的真实 100000 × 200 sparse/dense/islands 文件。
2. 完整行列数量、非空单元格数量、800 / 19899801 / 2233311 变化数量，以及尾单元格 GR100000 的两侧值正确。
3. strict/content、三布局、首尾导航、搜索、公式、复制、自动列宽、隐藏和合并语义一致。
4. 首屏 ready 代表真实窗口已绘制；不能以占位行数或截断结果通过。
5. 连续滚动后窗口缓存有界；取消、切换、关闭和异常路径释放资源；拒绝过期响应。
6. 小型功能回归与旧比较规则对照通过后，再运行真实压力样本；分别记录 Rust、Electron、renderer 的耗时和峰值内存。
